# Maintain the Kodi repository

The repository feed and IntroSkip service source are separate projects.

- **Repository:** this project, [repository.introskip](https://github.com/zoeywowy/repository.introskip)
- **Service source:** [service.introskip](https://github.com/zoeywowy/service.introskip)

## Publish an update

1. Release a new service version from `service.introskip`. Increment the version in its `addon.xml` for every installable code release.
2. Open **Actions → Build Kodi repository** in this project.
3. Select **Run workflow**.
4. Wait for package validation and GitHub Pages deployment to succeed.
5. Check the public installer page and package feed before asking users to update.

The workflow builds the service ZIP from the service repository, creates the repository index and MD5 checksum, packages both add-ons, and deploys the first-install page.

## Repository layout

```text
repo/
├── repository.introskip/
│   └── addon.xml
└── zips/                         # generated by Actions
    ├── addons.xml
    ├── addons.xml.md5
    ├── repository.introskip/
    └── service.introskip/
```

Do not hand-edit generated files under `repo/zips/`. The workflow rebuilds them from the two source manifests.

## Kodi 22 bootstrap link

Kodi's HTTP directory browser only recognizes the expected anchor format. Keep the generated link in this exact shape, with `href` first and the filename repeated as the visible text:

```html
<a href="repository.introskip-<version>.zip" class="download">repository.introskip-<version>.zip</a>
```

The workflow tests the generated and deployed HTML against Kodi's anchor parser, downloads the bootstrap ZIP, and verifies its contents.

The repository add-on points to raw GitHub URLs for `addons.xml`, `addons.xml.md5` and the versioned ZIP directory. GitHub Pages is only the Kodi File Manager bootstrap source.
